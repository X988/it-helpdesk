## Проверки исправлений

CI запускает:
1. Чистый npm ci и npm audit для полного дерева.
2. Prisma validate/generate, применение обеих миграций и повторное deploy.
3. Сравнение БД со схемой с exit-code.
4. TypeScript и ESLint.
5. Unit-тесты политик/входов/CSRF/файлов.
6. Интеграционные тесты с PostgreSQL 17: реальные ограничения/транзакции/гонки.
7. Production-сборку и bootstrap на синтетической БД.
8. HTTP-сценарий против настоящего Next.js сервера.
9. Сборку Docker runtime, наличие Prisma Client и полный HTTP-сценарий внутри контейнера.

S3-транспорт и отправка Telegram в интеграционных тестах контролируемые,
без реальных внешних сообщений. Подписывание download URL проверяется настоящим SDK.
Проверка реальных credentials, приватности bucket и зарегистрированного
webhook выполняется на стенде владельца.

Итоговые результаты конкретного запуска фиксируются в PR / GitHub Actions.
Непройденная или ещё не запущенная проверка не считается успешной.

## Решения и ограничения

- Это одна внутренняя служба, не мультиарендная SaaS-платформа.
- ADMIN управляет заявками и пользователями; TECHNICIAN видит очередь и
  управляет назначенными ему заявками; автор подтверждает решение.
  Доступ специалистов к общей переписке — сознательная политика.
- Новые сессии требуют повторного входа после обновления.
- Next.js 16.3.8 выбран после официального [обновления безопасности 30.09.2026](https://nextjs.org/blog/september-2026-security-release).
- Prisma 6 сохранена ради существующего формата схемы. deepmerge-ts
  переопределён на исправленную 8.0.2; совместимость подтверждается validate,
  generate, миграциями, тестами и сборкой.
- ESLint 9 закреплён из-за peer-совместимости текущего jsx-a11y;
  это инструмент разработки, не веб-сервер. Обновлять вместе с поддержкой плагина.
- Отдельная Android-ветка не является частью серверного продукта; её последние
  Actions завершились успешно. README Android предлагает ./gradlew при
  отсутствии wrapper; фактическая сборка CI использует gradle 8.13.
  Полный Android runtime-аудит в этот веб-релиз не входит.
- Криптографическая подпись файла не проверяется; сигнатура MIME не заменяет
  антивирусный анализ. Файлы принудительно скачиваются, bucket должен быть закрыт.
- При аварии процесса между S3 и БД возможен осиротевший объект; нужна сверка
  inventory bucket с TicketAttachment. Обычная ошибка компенсируется удалением.
- Уведомления допускают повтор после неопределённого ответа Telegram.
  Операции назначения/закрытия не дублируют изменения БД.
- При разрыве сети после успешного создания заявки до получения её ID
  клиент не может достоверно знать результат; оператор проверяет список перед
  повтором. Повторная загрузка файлов при известном ID не создаёт новую заявку.
- Бэкап/восстановление, TLS, DNS, реальные S3/Telegram и нагрузка конкретного
  предприятия требуют проверки на его инфраструктуре.
- Сквозная ручная проверка в браузере, оценка экранного диктора и полноценный
  пентест не заменяются HTTP/автоматическими тестами.
- main не защищена branch protection; правило обязательного CI относится к
  настройкам владельца репозитория, не менялось в коде.
- Абсолютной защиты и гарантии отсутствия дефектов этот аудит не заявляет.
